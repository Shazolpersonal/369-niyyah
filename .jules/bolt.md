
## 2024-04-18 - Memoizing DailyQuote and Achievements
**Learning:** `DailyQuote` component was re-rendering unnecessarily when its parent `Dashboard` re-rendered. Since its only true dependency is the `language` context, it is a prime candidate for `React.memo`. Similarly, `Achievements.tsx` was recalculating the badges array on every render using `getAchievements`. Since `getAchievements` processes the entire `dailyProgress` dictionary, it's an expensive operation that should be memoized using `useMemo`.
**Action:** When working with list rendering or standalone display components that rely on context or static props, evaluate the cost of re-rendering. Use `React.memo` for components and `useMemo` for expensive array/object generation to avoid unnecessary processing.

## 2024-04-18 - React.useMemo object dependency invalidation and Array allocations inside render loops
**Learning:** In `app/(tabs)/history.tsx`, the `monthStats` `useMemo` dependency array included `effectiveToday`, which was assigned `getEffectiveTodayDate()` (a new `Date` object instantiated on every render). This broke the memoization because object reference equality (`!==`) failed on every render, causing the expensive loop to run repeatedly. Additionally, inside the loop, `new Date()` was being instantiated 30 times per render to compare against `effectiveToday`. In `utils/achievements.ts`, `Object.keys` and `Object.values` were being used which allocates O(N) arrays every time.
**Action:** When using `useMemo` or `useEffect`, never put a newly instantiated object (like a `Date`, Array, or Object) in the dependency array unless it's memoized itself. Use string primitives (like `todayKey`) for dependencies. Instead of creating `Date` objects in loops for comparison, format dates to ISO strings (`YYYY-MM-DD`) and use lexicographical string comparison (`dateKey > todayKey`) to completely avoid object allocations. Avoid array allocations in frequent calculations by using simple loops with early exits.
